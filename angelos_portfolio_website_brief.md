## 1. Purpose

The website should bring together my scientific, technical, academic, outreach, and creative work in one place. I want it to work both as a **professional portfolio** for potential employers and collaborators and as a **long-term, growing archive** of projects I have completed over the years.

People visiting the website should be able to:

- Understand who I am and what I work on.
- Browse university, research, data-analysis, and programming projects.
- Read about my current master's thesis separately from other projects.
- Explore my science outreach and public-engagement experience.
- Watch videos and timelapses and view a selection of photographs.
- Access and download versions of my CV easily.
- Contact me through a simple contact method and professional links.

The website should feel like a coherent personal portfolio, **not** a collection of course assignments or a long online CV. It should emphasize the actual work, visuals, explanations, and results.

### Project index design

Each project should appear as a visual card with:

- Cover image, figure, plot, or appropriate thumbnail.
- Title and short one- or two-sentence summary.
- Year and optional institution/course.
- Relevant tags (e.g., Python, Data Analysis, Optics, Machine Learning).
- Link to the complete project page.

The Projects page should support **filtering by category or tags**. A search field is optional, not necessary at launch.

### Reusable individual project page

Each project page can contain the following, when available:

1. **Title and overview:** What the project was, and its goal.
2. **Context:** University/course/research group, date, collaborators or supervisor where relevant.
3. **My role:** What I personally did.
4. **Methods and tools:** Data, instrumentation, software, analytical approaches, etc.
5. **Process:** Key steps, challenges, or technical decisions.
6. **Results and visuals:** Figures, diagrams, animations, photographs, and key findings.
7. **Files and links:** Downloadable PDF reports, presentations, code/GitHub repositories, or other approved materials.
8. **Related projects:** Optional links to similar work.

Not all these fields must be filled. Larger projects get detailed pages; smaller assignments can have compact pages. Prefer clear explanations and evidence of work over excessive technical text.

## 11. Design and Experience Preferences

These are **design directions**, not fixed aesthetic requirements:

- Professional, modern, clean, and visually engaging.
- More visual and portfolio-like than a text-heavy institutional academic site.
- Strong project imagery: plots, photographs, scientific visuals, video previews.
- Consistent typography, comfortable spacing, and readable content.
- Works well on desktop and mobile.
- Good accessibility: alt text, keyboard-accessible navigation, sufficient contrast, and captions where appropriate.
- Fast loading: optimized image formats, lazy-loading media, embedded videos rather than massive files.
- Light, restrained animations are fine; avoid distracting effects.
- A consistent global navigation and footer.

Do **not** use fabricated scientific figures, invented portfolio photos, fake testimonials, or made-up research results as if they were my work. Temporary placeholder blocks are acceptable while content is being gathered, but they should be clearly marked.

## 12. Easy Updates and Long-Term Growth

One of the main requirements is that adding projects later should be straightforward.

Prefer a reusable, **content-driven structure**, where a new project can be added by supplying:

```yaml
# Example project record / front matter (illustrative)
title: "Project title"
slug: "project-title"
year: 2026
status: "completed" # or "ongoing"
category: "Research & Instrumentation"
tags: ["Python", "Data Analysis"]
summary: "Short project summary"
featured: false
cover_image: "" # add approved image path
report_pdf: "" # optional
repository_url: "" # optional
video_url: "" # optional
```

The main Projects page should populate automatically from these records. Give each item a stable page URL. Use similar reusable entries for outreach and visual works, while keeping their page designs appropriate to the different kinds of content.

The site should support future expansion into post-master's research, professional projects, talks, new videos, or other work without a structural redesign.
